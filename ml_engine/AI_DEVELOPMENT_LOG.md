# RiskFlow AI Development Log & Governance Record

## 1. AI Integration Architecture
- **Provider**: Groq Cloud API (LPU Inference Engine)
- **Model**: `llama-3.3-70b-versatile`
- **Execution Endpoint**: Server-side proxy (`/api/ai/analyze`), keeping API credentials strictly isolated from client bundles.

## 2. Prompt Engineering & Grounding Iterations
- **Strict Schema Enforcement**: Constrained the output format to RFC-8259 compliant JSON matching the `AiAnalystResponse` interface (`summary`, `riskDrivers`, `conclusion`, `evidence`, `metrics`, `affectedEntities`, `confidence`, `recommendation`).
- **Citation Anchoring**: Enforced strict referencing of verified evidence IDs generated by deterministic engines (`RA-101`, `PE-002`, `IV-001`, `PAT-017`).
- **Prompt Injection Defense**: Explicit system instructions specify that all input fields must be treated as DATA rather than actionable instructions, neutralizing malicious payloads inside borrower descriptions or uploaded CSVs.

## 3. Engineering Decisions & Validations
- **Human Oversight**: All proposed intervention protocols require explicit confirmation from a Risk Analyst before executing downstream status changes.
- **Audit Lineage**: Every AI consultation is recorded to an immutable regulatory ledger logging query timestamp, model version, source entity ID, and response payload.
